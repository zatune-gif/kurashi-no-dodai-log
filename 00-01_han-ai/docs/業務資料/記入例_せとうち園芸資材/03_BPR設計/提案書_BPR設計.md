- 作成日：2026-09-20
- 作成：ざつね屋（連絡先：zatuneya@gmail.com）
- 対象プロセス：受注〜出荷〜請求の一連の流れ（うち第2段階の主対象は受注〜出荷）

> ※これは記入例です。実在の会社ではありません。

---

## 1. 現状の理解

- 受注は電話・FAX・メールの3経路で入り、営業事務3名が対応している
- 受注をシステムに入力した後、紙の受注控えにも書き写している（二重）
- 在庫確認は倉庫担当1名が1日1回まとめて行っており、受注から出荷まで平均3.5日かかっている
- 出荷リストは出荷指示書から手入力で作り直している（二重）
- 春・秋の繁忙期は、営業事務の残業が月40時間超

**そこから見える課題**

- 流れ自体に無理がある：同じ情報を複数回入力しており、在庫確認が全体の律速になっている
- 部分的な効率化（過去にFAX-OCRを試行）では、出荷までの日数は変わらなかった

## 2. ご提案するアプローチと、その理由

まず**業務改善設計**で受注事務を可視化し、投資ゼロの改善（紙控え廃止・出荷リスト自動化）で足場をつくります。
続いて**BPR設計**で、受注〜出荷の流れをゼロベースで作り直します。

理由：

- 問題が特定の作業ではなく、部門（営業事務⇄倉庫）をまたぐ「流れ」にある
- システムを入れたのに紙作業が残っている（手段が先行した状態）
- 社長が関与でき、やり方を変える権限・予算がある

> 在庫最適化・需要予測（DX）は、在庫データが整ってからの将来テーマとし、今回は対象外とします。

## 3. 対象範囲

| | 内容 |
|---|---|
| 対象とするプロセス | 注文を受け取る 〜 出荷する（請求は現状維持） |
| 関わる部門 | 営業・営業事務・倉庫 |
| 今回は対象としない範囲 | 請求業務、仕入・発注業務、配送手配、在庫最適化（DX） |
| 前提（変えられないもの） | 現行の販売管理システムを基幹として使い続ける |

## 4. 進め方（3段階・8ステップ）

（テンプレート `提案書テンプレート_BPR設計.md` の表と同じ。第1段階＝業務分析、第2段階＝施策検討、第3段階＝施策実施）

- 第1段階（約1か月）：受注事務の洗い出し → AS-IS作図 → 原因分析 → 課題整理
- 第2段階（約1か月）：施策検討（A/B/C案）→ TO-BE設計 → 移行計画
- 第3段階（約2か月）：在庫のクラウド共有を立上げ、KPIで効果検証

## 5. 成果物

- 現状の業務フロー図（AS-IS）／あるべき業務フロー図（TO-BE）
- 業務一覧表・業務スキルマップ
- 問題・原因・課題の整理表
- 施策一覧と優先順位（投資額別の3案）
- 移行計画（対象外の範囲も明記）
- KPI定義と検証結果
