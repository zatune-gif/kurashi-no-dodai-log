# ざつね屋 Webサイト v3 TOPページ実装指示

既存の「ざつね屋」Webサイトを次期バージョン（v3）へ全面改訂します。

今回作成したTOPページのデザインカンプを基準として、既存の静的HTMLサイトへ実装してください。

## 1. 今回の目的

単なる「AIサービス会社」のサイトではなく、

**ざつね屋 ／ 地域企業の小さな業務変革屋**

として再設計します。

事業の中心はAIそのものではありません。

地域企業の困りごとを起点として、

業務整理  
→ 人の育成  
→ 小さな仕組みづくり  
→ 効果確認  
→ 横展開・内製化

までを一本の線で支援する「業務変革の伴走」が事業の本質です。

サイト全体でも、

**「AIを導入する」より「仕事をよくする」**

ことを上位概念として表現してください。

# 2. 最重要メッセージ

TOPページのH1は以下です。

**AIを入れることより、  
仕事がよくなることから。**

肩書は、

**地域企業の小さな業務変革屋 ／ ざつね屋**

とします。

ファーストビューでは、このメッセージを最も強く見せてください。

---

# 3. デザインの基本方針

今回のカンプは「レイアウト・情報優先順位・視覚トーン」の正本として扱ってください。

ただし、カンプ内の生成画像には一部不自然な箇所があるため、**ファーストビュー以外の写真については最終素材ではありません。**

写真は後から差し替えます。

したがって実装では、

- 写真の表示領域
- アスペクト比
- object-fit
- object-position
- レスポンシブ時のトリミング
- カード内での写真サイズ

を適切に設計し、画像ファイルを交換するだけで成立する構造にしてください。

画像に合わせてレイアウトを固定しないでください。

---

# 4. ファーストビュー

ファーストビューの方向性は確定しています。

「一人でPCや資料を確認している人」ではなく、

**地域企業の担当者と支援者の2人が、同じ業務資料を挟んで話しながら業務を整理している場面**

を使用します。

顔を主役にしません。

見せたいのは、

- 一緒に考える
- 現場に入る
- 業務を整理する
- 対話する
- 伴走する

という関係性です。

PCやAI画面を主役にしないでください。

AIチップ、ロボット、回路、未来的UIなどの「AI企業らしい記号表現」は不要です。

# 8. レイアウト

PCでは中央コンテナ方式とし、極端な横長にならないよう最大幅を設定してください。

PC 32〜48px程度  
Tablet 24〜32px  
Mobile 20px前後

を基本とします。

4pxグリッドに合わせて最終調整してください。

# 20. アイコン

絵文字は禁止です。

# 21. 写真

重要です。

写真は、

**「AI」ではなく「仕事」を見せてください。**

推奨：

- 業務資料
- 打ち合わせ
- 手元
- ホワイトボード
- 書類整理
- PCを使った実務
- 業務フローを一緒に確認している場面

避ける：

- ロボット
- AIチップ
- 脳＋回路
- SF的なUI
- 青く光るホログラム
- 握手だけのストック写真
- 意味のない会議写真

顔が判別できない構図を基本とします。

代表者写真のみ例外です。

---

# 22. 写真素材についての注意

現在のカンプに含まれるファーストビュー以外の生成写真は**仮素材**です。

これまで、

- 指の形がおかしい
- 指とペンが一体化する
- 一人がペンを二本持って見える
- 存在しない人物の手が写り込む
- PCの上にカップが置かれる

など生成画像特有の問題が発生しています。

そのため、それらをデザインの正本として再現しないでください。

画像は後から正式素材へ差し替えます。

# 24. レスポンシブ

Desktopをそのまま縮小してMobileにしないでください。

Mobileでは、

- 3カラム → 1カラム
- 4カラム → 2または1カラム
- 横長STEP → 縦STEP
- 大きな写真 → 適切にトリミング
- CTA → 原則フル幅
- 長文 → 適切な改行幅

へ再構成してください。

特にスマートフォンでは、

**一画面に情報を詰め込みすぎないこと**

を重視してください。

---

# 25. 視認性について

今回のv3で重要な改善点です。

旧カンプでは文字量が多く、視認性が落ちる問題がありました。

そのためTOPページでは、

**全部説明するのではなく、理解させて下層へ送る**

ことを基本にしてください。

文章だけで説明できる場合でも、

- 写真
- アイコン
- 数字
- ステップ
- 短いコピー
- 余白

へ変換できないか検討してください。

ただしカードだらけのサイトにもしてくださいません。

---

# 26. アクセシビリティ

WCAG 2.1 AAを目標とします。

最低限、

- 色コントラスト
- keyboard focus
- hover以外でも状態が分かる
- タップ領域44px以上
- alt属性
- semantic HTML
- heading hierarchy
- button / anchorの適切な使い分け

を守ってください。
