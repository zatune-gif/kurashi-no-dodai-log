## 2. データ状態の区別ルール（最重要・崩さない）

半農の情報を `hannou.html` などに反映するときは、数値・事実に必ず状態ラベルを付け、区別を混同しない。

| ラベル | 意味 | 例 |
|---|---|---|
| 確認済（confirmed） | 一次資料で確認できた事実 | No.9 の面積 324㎡（課税明細書上の面積） |
| 概算（estimated） | 目安の数値。精査していない | 作付面積・株数・作業委託費 約10万円/年（家族談） |
| 計画（planned） | これからやる予定。未実行 | 初年度3作物、ロードマップ Phase・マイルストーン |
| 未確認（unknown） | 未調査・未確定 | 権利関係、排水能力、高低差、土壌pH・成分 |

**やってはいけないこと**

- 過去の検討値を、確定値のように書くこと。
  例: 堆肥 600〜900kg／苦土石灰 30〜40kg は「過去検討値／未決定」であって確定支出ではない。
- 同じ対象なら全項目が同じ状態、と思い込むこと。
  例: No.9 は「面積＝確認済」だが「権利関係＝未確認」。項目ごとに状態が違う。
- 方針を変えたときに、古い記述を黙って消すこと。
  →「いつ・何が分かって・なぜ変えたか」を履歴として残し、既存記述は消さない。

**なぜ**: GPT からの引き継ぎで繰り返し強調された点。過去に方針・検討値がそのまま確定情報として
扱われたことへの警戒。`hannou.html` ではこれを `.dtag`（`dtag-ok` / `dtag-est` / `dtag-plan` /
`dtag-unknown`）と `.st`（台帳ステータス chip）で表現している。

## 4. No.9 休耕田畑化・自給農プロジェクト

- **場所**: 広島県福山市新市町大字常 1285-2。課税資料上の地目＝田、面積＝324㎡（約3.24a・約98坪、確認済）。
- **基準写真**: 2026年8月時点の現況写真＝「畑化前」の基準（※原本はこのリポジトリには未格納）。
- **位置づけ**: Aレイヤー「暮らしとしての農」の自給農・実証圃場。初年度は販売収益の最大化を目的にしない。
  Bレイヤー（妻の認定新規就農者手続き）は並行する別トラック。No.9 の完了を待たずに就農相談を進める。
  No.9 の実測データ（作業時間・収量・土地特性・必要資材・失敗）は将来の5か年農業経営計画の参考にする。
- **ステータス**: 2026-08-29 に「計画」→「実行準備フェーズ」へ移行。
  初年度実証期間 = 2026年秋〜2027年秋。最初の作業 = 雨後の排水調査（元水田のため排水が最重要課題）。
  行政確認前に不可逆な大規模工事はしない。
- **圃場方針**: 324㎡ 全面を畑にしない。実作付区／緑肥区／管理区 の3区分で段階的に。
- **初年度3作物**（すべて計画段階、面積は概算）:
  玉ねぎ（2026年秋開始・10〜15㎡・苗250〜350本）／じゃがいも（2027年春・20〜30㎡）／
  里芋（2027年春・10〜20㎡）。サツマイモは見送り（じゃがいもを優先）。
- **予算イメージ**（確定支出ではない）: DIY中心 3〜7万円、機械作業込みで最大10万円程度まで検討。
- **農機**: 結果が分かるまで専用機械を買わない。購入／中古／レンタル／共同利用／委託を比較。
  No.6・No.7 水田作業の内製化と併せて判断。

  土壌診断 → 必要量算定 → 必要な場所だけ、の順。

## 5. `hannou.html` を編集するときの約束事

- CSS デザイントークン12値（`--teal` 系・`--orange`・`--bg`・`--surface`・`--ink` 系・`--border`・
  `--ok` / `--warn` / `--danger`・`--radius`・`--shadow`）は4ページ共通。**値を変更しない**
  （`index.html` のコメントに明記）。各ページが `:root` に同じ12値を複製している。
- 追加スタイルは既存クラス（`.table-wrap` / `.mission-block` / `.view-block` / `.policy-note` /
  `.info-bar` / `.unknown-card` / `.jikyu-stack` / `.priority-list` / `.roadmap` など）を再利用する。
  新規クラスもトークンで組む。**インライン style は使わない**（既存ファイルに数箇所あるが踏襲しない）。
- 略語を使わない。初見の人が見た瞬間に意味が分かる表記にする。
- データを載せるときは第2節の状態ラベルを必ず付ける。
- 編集環境は Mac（`/Users/zatuneya/work/ClaudeCode/kurashi-no-dodai-log`）。
  ルート `CLAUDE.md` / `AGENTS.md` の `C:\Users\ooto\...`・PowerShell 記述は別マシン向けで、
  Mac 環境には当てはまらない。
- ローカル検証は Chrome のヘッドレスを使う
  （`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless --screenshot`）。
  node / npx / Playwright は未インストール。`--headless=new` はプロセスが残るので旧 `--headless` を使い
  PID で kill する。`pkill -f "Google Chrome"` は実ブラウザを巻き込むので使わない。
